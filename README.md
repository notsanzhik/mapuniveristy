# ХДУ Map — React + Node.js + SQLite

Интерактивная карта университета: два корпуса, 13 векторных поэтажных планов, 170 помещений и фрагментов, поиск и маршруты на русском и казахском языках.

- **А корпус** (`five`): подвал — этаж `0`, затем этажи `1–5`.
- **Б корпус** (`seven`): этажи `1–7`.

## Запуск

Нужны **Node.js 24+** и pnpm. SQLite используется через встроенный модуль `node:sqlite`; отдельный сервер базы данных не нужен.

```sh
pnpm install
pnpm build
pnpm start
```

Откройте [локальную карту](http://127.0.0.1:8765/). По умолчанию сервер слушает `HOST=127.0.0.1`, `PORT=8765`. Эти переменные окружения меняют адрес и порт.

Для разработки с обновлением React-компонентов:

```sh
pnpm dev
```

Проверки:

```sh
pnpm test
```

Команда запускает Node test runner для `tests/*.test.js`. Production-сборка создаётся командой `pnpm build` в `dist/`.

**Одного каталога `dist/` теперь недостаточно:** интерфейс загружает карту, поиск и маршруты через Node API. Для работы приложения нужен запущенный `server.mjs`, серверные модули, общие исходные данные/функции и зависимости проекта. Открытие `dist/index.html` как отдельного файла или размещение только `dist/` на статическом хостинге не заменяет сервер.

## Хранение данных

По умолчанию база находится в `var/hdu-map.sqlite`. При первом запуске пустая база получает корпуса, этажи, помещения и ревизию из `src/data.js` в одной транзакции. При следующих запусках существующая база читается и **не перезаписывается исходным seed**. Изменение `src/data.js` само по себе не обновляет уже созданную базу.

`HDU_DB_PATH` задаёт другой локальный файл. Разрешены только пути внутри каталога проекта `var/` либо системного временного каталога; выход через символьные ссылки также отклоняется. Режим `:memory:` предназначен для тестов и не сохраняет данные после закрытия процесса. URL не используются как путь к базе.

Для резервной копии остановите Node-сервер, дождитесь его завершения и скопируйте файл базы в отдельное место. Рабочая база и её временные файлы не должны попадать в распространяемый архив проекта. При восстановлении верните копию в разрешённый каталог перед запуском сервера.

Публичный API предоставляет чтение данных и расчёт маршрутов. Изменение номеров и названий доступно только через отдельный API администратора после входа. Обновление SQLite-схемы 1→2 выполняется в транзакции при запуске и сохраняет существующие кабинеты, геометрию и ревизию.

## Админ-панель

Откройте [администрирование](http://127.0.0.1:8765/admin). При первом открытии на компьютере сервера задайте пароль длиной 12–128 символов. Готового общего пароля нет. Начальная настройка разрешена только через loopback-соединение и адрес `localhost`, `127.0.0.1` или `::1`; для переноса на сервер настройте доступ локально до публикации. Затем вход выполняется тем же паролем. В базе хранится только случайно посоленный scrypt-хеш.

Выберите корпус, этаж и помещение в списке. Можно изменить номер (пустое значение убирает номер), русское название и казахское название. Ведущие нули и буквы сохраняются. Пустое казахское название использует существующий перевод, а при его отсутствии — русское название. Геометрию, двери, тип помещения и технический ID форма не изменяет. Два помещения на одном этаже одного корпуса не могут получить одинаковый номер; регистр и латинские A/B учитываются как соответствующие кириллические буквы.

Сохранение изменяет SQLite, обновляет ревизию и добавляет запись «до/после». Последние 20 изменений видны для выбранного помещения. При устаревшей ревизии сервер возвращает конфликт: черновик остаётся в форме, а администратор может загрузить актуальные данные перед повторным сохранением. Подписи на карте обновляются при возвращении во вкладку и после сигнала из панели; открытые подсказки поиска также получают новую ревизию.

Сессия живёт до 8 часов, хранится на сервере и прекращается после выхода или перезапуска процесса. Cookie имеет `HttpOnly`, `SameSite=Strict` и ограниченный путь; изменение данных и выход требуют CSRF-токен и проверку Origin. Cookie становится `Secure` при TLS либо при HTTPS в `HDU_PUBLIC_ORIGIN`. За HTTPS-прокси задайте `HDU_PUBLIC_ORIGIN=https://ваш-домен` как переменную окружения процесса: это точный публичный origin без пути, а заголовкам `X-Forwarded-*` сервер не доверяет. Пароль и токены не сохраняются в localStorage.

Пароль пока один для всех уполномоченных администраторов. Отдельные учётные записи, смена/восстановление пароля и редактирование геометрии в эту версию не входят.

Для реализации использованы встроенный [Node.js crypto.scrypt](https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback) и рекомендации OWASP по [хранению паролей](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#scrypt), [CSRF](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) и [сессиям](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

| Метод | Путь `/api/v1/admin` | Назначение |
| --- | --- | --- |
| GET / HEAD | `/session` | Состояние настройки/входа и CSRF-токен вошедшего администратора |
| POST | `/setup` | Первое создание пароля с локального компьютера |
| POST | `/login` | Вход по паролю |
| POST | `/logout` | Завершение текущей сессии |
| GET / HEAD | `/rooms?building=five&floor=1&q=...` | Защищённый список помещений |
| PATCH | `/rooms/:building/:floor/:id` | Сохранение `{number,labelRu,labelKk,revision}` |
| GET / HEAD | `/history/:building/:floor/:id` | Последние 20 записей «до/после» |

Для POST и PATCH необходим `Origin`; для PATCH и logout — также `X-CSRF-Token` и cookie сессии. Все ответы администрирования используют `Cache-Control: no-store`. Неудачные попытки входа ограничены отдельно: пять за десять минут на непосредственный IP соединения. Секреты и история не входят в публичные карты и архив проекта; исходные тесты содержат только отдельные тестовые пароли.

## API v1

Базовый путь — `/api/v1`. Успешные ответы имеют вид:

```json
{"data": {}, "revision": "sha256-ревизия набора данных"}
```

`data` содержит объект или массив в зависимости от метода. `revision` — строка из 64 шестнадцатеричных символов. Публичная проекция сохраняет геометрию и номера, но исключает площади, имена исходных PDF, страницы экспликаций и ссылки на сканы.

| Метод | Путь | Результат |
| --- | --- | --- |
| GET / HEAD | `/maps` | Обе карты с этажами и помещениями |
| GET / HEAD | `/buildings` | ID, код, русское/казахское название и список этажей каждого корпуса |
| GET / HEAD | `/buildings/:building/floors/:floor` | Один этаж с геометрией помещений |
| GET / HEAD | `/search` | Найденные помещения с `building` и `floor` |
| POST | `/routes` | Схематический путь между двумя каноническими точками |

Диагностика сервера доступна отдельно: `GET /api/health` и `HEAD /api/health`.

### Поиск

Параметры `/search`:

| Параметр | Назначение |
| --- | --- |
| `q` | Номер или русское/казахское название; максимум 120 печатных символов. Пустой запрос допустим для подсказок |
| `building` | Явный фильтр по `five` или `seven` |
| `floor` | Явный фильтр по существующему целому номеру этажа |
| `contextBuilding` | Текущий корпус для ранжирования, без ограничения других корпусов |
| `contextFloor` | Текущий этаж для ранжирования; требует `contextBuilding` и существующего в нём этажа |
| `routeOnly` | `true` исключает неполные фрагменты; по умолчанию `false` |
| `limit` | Количество результатов от `1` до `60`; по умолчанию `60` |

Без фильтров поиск охватывает оба корпуса и все этажи. Например, `/api/v1/search?q=305&contextBuilding=five&contextFloor=1` находит кабинет 305 на третьем этаже А корпуса. Контекст А корпуса также не скрывает кабинет 211 в Б корпусе. Для интерфейса текущую позицию следует передавать через `contextBuilding/contextFloor`, а не через фильтры.

Пустой результат корректного поиска возвращает `200` и `data: []`. Неизвестные или повторяющиеся параметры, недопустимые этажи и значения возвращают ошибку проверки запроса.

### Маршрут

`POST /api/v1/routes` принимает `Content-Type: application/json` и тело до **8192 байт**:

```json
{
  "from": {"building": "five", "floor": 1, "id": 14},
  "to": {"building": "five", "floor": 3, "id": 5}
}
```

Этот пример связывает лестницу первого этажа с кабинетом 305. `id` — идентификатор помещения из данных API, а не номер кабинета. Сервер сам находит обе точки в базе; переданные клиентом координаты, подписи и другие дополнительные свойства не подменяют канонические данные.

Путь между корпусами, совпадающие точки и неполные планы получают отдельные ошибки. При отсутствии непрерывного пути маршрут не придумывается. Расстояния и время ходьбы не вычисляются.

### Ошибки, кэш и ограничения

Ответ об ошибке:

```json
{"error": {"code": "VALIDATION_ERROR", "message": "Diagnostic message"}}
```

Интерфейс использует `error.code` для русского или казахского сообщения; диагностический английский `message` не требуется показывать студентам.

- `400`: `INVALID_QUERY`, `INVALID_JSON`, `VALIDATION_ERROR`.
- `404`: `NOT_FOUND`.
- `405`: `METHOD_NOT_ALLOWED`, с заголовком `Allow`.
- `413`: `PAYLOAD_TOO_LARGE`; лимит проверяется и для потокового тела без `Content-Length`.
- `415`: `UNSUPPORTED_MEDIA_TYPE`.
- `422`: `CROSS_BUILDING`, `PARTIAL_PLAN`, `SAME_POINT`, `NO_ROUTE`.
- `429`: `RATE_LIMITED`, с `Retry-After`.
- `500`: `INTERNAL_ERROR`, без внутренних путей или содержимого запроса.

Для `/api/*`, кроме `/api/health`, действует лимит **1000 запросов за 60 секунд на адрес непосредственного TCP-соединения** (`req.socket.remoteAddress`). `X-Forwarded-For` не считается доверенным источником IP. За обратным прокси его подключения будут делить этот лимит; отдельная настройка доверенных прокси в этой версии не добавлена.

URL ограничен 2048 символами, размер HTTP-заголовков — 16 КБ. На получение запроса и заголовков установлены таймауты. Лимиты проверены функциональными тестами; это не результат нагрузочного тестирования.

Карты, метаданные корпусов и этажи используют `ETag` и `Cache-Control: no-cache`: совпавший `If-None-Match` получает `304` без тела. Поиск и маршруты возвращаются с `Cache-Control: no-store`. Статика из `dist/` отдаётся с MIME-типами, gzip и длительным кэшированием ресурсов с хешами.

## Устройство проекта

- `src/App.jsx` — состояние React-интерфейса, загрузка данных и работа с API.
- `src/components/MapCanvas.jsx` — SVG-карта, hover/bubble, перетаскивание, pinch и масштаб.
- `src/components/SearchPicker.jsx` — управляемый поиск и выбор точек с клавиатуры.
- `src/components/RoutePlanner.jsx` — «Откуда → Куда» и шаги маршрута.
- `src/map-core.js` — общие чистые функции поиска и построения пути.
- `src/data.js` — исходный seed с нумерацией и геометрией.
- `src/i18n.js` — русские и казахские переводы.
- `src/styles.css` — темы, адаптивность и анимации.
- `public/assets/` — локальные шрифт и эмблема.
- `server.mjs` — Node HTTP-сервер, статика/Vite, таймауты и ограничение частоты запросов.
- `server/api.js` — API v1, валидация и публичная проекция данных.
- `server/repository.js` — SQLite-схема, первоначальное заполнение и чтение базы.
- `server/admin-api.js` — настройка администратора, вход, сессии, CSRF, сохранение и история.
- `src/admin/` — отдельная панель, её API-клиент и стили; загружается только на `/admin`.
- `reference/` — материалы для сверки и прежние тесты; в `dist/` не публикуются.

## Карта и оформление

Номер кабинета отделён от номера помещения по экспликации. Ведущие нули и буквенные суффиксы сохранены. Площади и просмотр исходных чертежей исключены из студенческого интерфейса.

Montserrat хранится локально. Реальные глифы русского и казахского алфавитов проверены по `cmap`, включая **Әә Ғғ Ққ Ңң Өө Ұұ Үү Һһ Іі**. Источник: [Google Fonts / Montserrat](https://github.com/google/fonts/tree/main/ofl/montserrat). Лицензия SIL OFL находится в `public/assets/fonts/Montserrat-OFL.txt`.

Белая с зелёным и тёмная с зелёным темы сохраняются на устройстве. Наведение выделяет кабинет золотой границей и показывает название с bubble-эффектом; область нажатия остаётся стабильной. Для сенсорных устройств и `prefers-reduced-motion` предусмотрено отдельное поведение.

В поиске и полях маршрута можно вводить номер или русское/казахское название независимо от языка интерфейса. Поддерживаются подсказки, ArrowUp/ArrowDown/Enter/Escape, смена направления и выбор точек из карточки на карте. Ссылка с открытой панелью: `?building=five&floor=1&lang=ru&planner=1`.

Эмблема предоставлена заказчиком. Внешний белый фон удалён встроенным `image_gen`; прозрачность снаружи и непрозрачная белая птица сохранены. Применённый запрос: «Only the exterior white background becomes transparent. Keep the white bird opaque. Preserve original shape and colors; no redesign.»

## Проверки и оставшиеся ограничения

Финальный прогон 21 октября 2026: **97 тестов прошли, 0 ошибок**. `pnpm test` проверяет логику карты, двуязычные тексты и реальные глифы шрифта, React-компоненты и сценарии приложения в DOM-среде, API-клиенты, HTTP API, SQLite, миграцию и перезапуск сервера. Дополнительно проверяются вход/выход, CSRF, ограничение попыток, права на запись, конфликты, дубли, история и сохранение черновиков. Сохранено точное совпадение координат 121 схематического маршрута с прежней версией. Production-сборка и HTTP-проверка запущенного сервера прошли; подробности находятся в `audit-report.json`.

ReactDOM/linkedom и HTTP-тесты не подтверждают визуальную раскладку в настоящем браузере. Автоматическая проверка локальной вкладки ранее была ограничена; внешний вид и жесты на реальных телефонах ещё требуют проверки. Нагрузочное тестирование и проверка маршрутов на месте не проводились.

Геометрия, двери и проходы упрощены по архитектурным чертежам. Перед студенческим запуском университет должен сверить действующие номера и реальные проходы. Обрезанные фрагменты пристройки исключены из маршрутов. Переход между корпусами и внутренняя геолокация не добавлены. Карта не является эвакуационной схемой.
